Policy Planning Document

LONGRISE 수탁형 지갑, 입출금 및 자금관리 정책 기획서

본 문서는 LONGRISE 플랫폼의 수탁형 지갑 구조, USDT 입출금, CNYT 내부 원장 관리, 한국 거래소 직접 입출금 차단, 오염 자금 격리, 가스비 최소화, 배치 출금 운영 기준을 개발자가 구현 가능한 정책 형태로 정리한 문서이다.

서비스 구조

100% Web3 기반 수탁형 지갑. 회사는 KYC 자료나 실명 개인정보를 수집하지 않는다.

USDT 체인

1단계는 TRC20 USDT만 지원하고, 3단계 이후 테더 주요 상위 3개 체인으로 확장한다.

출금 운영

1단계 최소 출금 10 USDT, TRC20 수수료 1 USDT 고정, UTC 09:00 기준 1일 1회 배치 처리.

2. 수탁형 지갑 구조

유저 화면에서는 개별 지갑과 잔액처럼 보이지만, 실제 운영은 플랫폼 수탁 지갑과 내부 Ledger로 처리한다. 패키지 구매, 매일 수익 분배, 보너스 지급, 내부 SEND, CNYT P2P 이동은 온체인 거래가 아니라 Ledger 기록이다.

지갑 / 계정 목적 운영 정책
User Deposit Address 유저별 입금 식별 입금 식별용 주소. 유저가 개인키를 보유하지 않으며 플랫폼이 수탁 관리한다.
Deposit Screening Wallet 입금 후 리스크 검사 구간 컨펌 완료 후 출처, 한국 거래소 직접 입금 여부, 고위험 주소 여부를 검사한다.
Quarantine Wallet 고위험 또는 오염 가능 자금 격리 정상 자금과 혼합 금지. 검토 전 Hot Wallet 이동 금지.
Hot Wallet 일일 출금 실행 정상 판정 자금만 유입. UTC 09:00 배치 출금 재원으로 사용한다.
Warm Wallet 출금 예비 자금 Hot Wallet 유동성 보충용. 운영 승인 후 이동한다.
Cold Wallet 장기 보관 대량 자금 보관. 다중 승인과 수동 절차를 기본으로 한다.
CNYT Central Wallet 회사 보유 CNYT 중앙 지갑 CNYT 발행, 보유, 분배, 회수 기준 지갑. 유저 CNYT는 Ledger 잔액으로 표시한다.

1단계 최소 집금 구조

1단계에서는 완전한 3-Tier 자동 지갑 구조를 만들지는 않더라도, 집금 정책 자체는 반드시 적용한다. 이유는 유저 입금 자금이 회사의 출금 재원이나 CEX 계정으로 직접 흘러 들어가면, 오염 가능 자금이 회사 운영 지갑과 출금 지갑 전체의 리스크로 전이될 수 있기 때문이다.

구분 1단계 정책 금지 사항
입금 계열 User Deposit Address → Stage-1 Collection Wallet 유저 입금 자금을 CEX, Payout Wallet, 회사 정산 지갑으로 직접 전송 금지
출금 계열 Payout Wallet → 유저의 승인된 출금 주소 Stage-1 Collection Wallet의 자금을 Payout Wallet로 직접 이동 금지
회사 자금 Payout Wallet은 회사가 별도 충전한 검증 자금으로 운영 유저 입금 자금과 회사 출금 재원을 장부상/온체인상 혼합 금지
1단계 핵심: 집금은 필요하지만 자동화는 최소화한다. 관리자는 집금 대상 주소와 금액을 확인한 뒤 수동 또는 반자동으로 Stage-1 Collection Wallet에 모은다. 이 지갑은 보관/검토용이며 출금 재원으로 직접 사용하지 않는다.

5. 한국 거래소 직접 입출금 차단 정책

차단 대상은 한국 거래소와의 직접 입출금이다. 개인지갑을 경유한 입출금은 차단하지 않는다. 즉 플랫폼이 직접 확인하고 통제하는 범위는 입금 직전 주소와 출금 목적지 주소를 기준으로 한다.

거래 흐름 처리 비고
한국 거래소 → 플랫폼 차단 / 검토 직접 입금으로 식별되면 자동 반영하지 않는다.
플랫폼 → 한국 거래소 차단 출금 주소가 한국 거래소로 식별되면 요청을 생성하지 않는다.
한국 거래소 → 개인지갑 → 플랫폼 허용 직접 입금이 아니므로 차단하지 않는다. 단, 고위험 주소 검사는 수행한다.
플랫폼 → 개인지갑 → 한국 거래소 허용 플랫폼 출금 목적지가 개인지갑이면 허용한다.

차단 구현 방법

  • 한국 거래소로 식별된 입금/출금 주소 목록을 내부 블랙리스트로 관리한다.
  • 체인 분석 API 또는 VASP 라벨링 데이터를 통해 거래소 주소를 식별한다.
  • 운영 중 발견된 한국 거래소 주소는 관리자 검토 후 블랙리스트에 추가한다.
  • 출금 주소 입력 시 실시간으로 한국 거래소 주소 여부를 검사한다.
  • 입금은 블록체인상 사전 차단이 불가능하므로, 감지 후 미반영/검토/거절 상태로 처리한다.

6. 입금 정책

  1. 유저가 플랫폼에서 TRC20 USDT 입금 주소를 확인한다.
  2. 입금 감지 시 Pending Confirmation 상태로 기록한다.
  3. 요구 컨펌 수 충족 후 Screening 상태로 전환한다.
  4. 직접 출처가 한국 거래소인지, 고위험 주소인지, 제한 거래소인지 검사한다.
  5. 정상 판정 시 Deposit Balance에 반영한다.
  6. 직접 한국 거래소 또는 중위험 출처로 식별되면 Pending Review 또는 Restricted로 처리한다.
  7. 고위험 또는 오염 가능 자금은 Quarantine Wallet 정책을 적용한다.
상태 의미 유저 화면 표시
Pending Confirmation 블록 컨펌 대기 Confirming
Screening 리스크 검사 중 Under review
Credited 정상 반영 완료 Credited
Pending Review 수동 검토 필요 Review required
Restricted 직접 차단 대상 또는 정책 제한 Restricted

7. 집금 정책

집금 정책은 1단계부터 적용한다. 단, 1단계의 목표는 자동화가 아니라 회사 자금 흐름의 안전한 분리다. 유저 입금 주소에 들어온 자금은 DB 반영 후에도 회사 출금 지갑이나 CEX로 직접 이동하지 않고, 별도의 Stage-1 Collection Wallet로만 모은다.

항목 1단계 기본 정책 2단계 고도화 방향
집금 대상 19 컨펌 완료, DB 입금 기록 완료, 관리자 확인 완료 입금 Basic On-chain Risk Screening GREEN 입금만 자동 집금
집금 기준 관리자 수동 판단. 기본값은 주소 잔액 100 USDT 이상 또는 마지막 입금 후 7일 경과 시 집금 검토 금액 기준, 시간 기준, 리스크 점수 기준을 조합한 자동 큐
집금 주기 1일 1회 또는 필요 시 수동 실행 운영 부하 분산을 위한 예약/랜덤 딜레이 배치
집금 목적지 Stage-1 Collection Wallet Buffer Wallet → Vault Wallet 구조로 확장
출금 재원 사용 집금 자금은 Payout Wallet로 직접 이동하지 않음 Vault와 Payout의 온체인 직접 연결 금지 원칙 유지
감사 로그 집금 실행자, 대상 주소, 금액, TxID, 사유 기록 집금 큐, 리스크 스코어, 승인자, 실패 사유까지 기록
1단계 집금 기준의 숫자값은 운영 기본값이다. 실제 운영 전 개발자와 운영자가 가스비, 입금 빈도, 유저 수, 관리자 처리량을 보고 조정할 수 있어야 한다.

8. Payout Reserve 정책

회사가 입금 받는 지갑과 유저에게 출금하는 지갑은 분리되어야 한다. 다만 상품 중도 해지와 매일 수익 지급, 일반 출금이 동시에 발생할 수 있으므로 Payout Wallet에는 별도의 유동성 기준이 필요하다. 이 정책의 목적은 유저 입금 자금을 Payout Wallet으로 직접 흘려보내지 않으면서도, 출금 지연과 회사 유동성 부족을 방지하는 것이다.

항목 정책값 운영 설명
기준 방식 통합 Reserve 방식 상품별로 복잡한 비율을 두지 않고, 전체 확정 패키지 구매금액을 하나의 기준으로 관리한다.
필요 Reserve 총 확정 패키지 구매금액 × 35% 운영 인력이 적은 1~2단계에서는 단순성과 유동성 안정성을 우선한다.
충전 주기 매월 10일, 25일 정기적으로 Payout Wallet 또는 Payout Reserve Wallet의 잔액을 점검하고 부족분을 회사 자금으로 보충한다.
주의 경보 필요 Reserve의 90% 미만 관리자 대시보드에 경고를 표시하고 다음 충전일 전 보충 필요 여부를 검토한다.
긴급 경보 필요 Reserve의 80% 미만 회사 자금 보충, 출금 배치 속도 조정, 중도 해지 처리 일정 조정 중 하나를 즉시 검토한다.
자금 이동 원칙 입금 라인과 출금 라인 직접 연결 금지 Collection/Vault 계열 자금은 Payout Wallet로 직접 이동하지 않고, Payout 재원은 회사가 검증한 별도 유동성으로 충전한다.
35% Reserve는 유저에게 노출하는 수익 보장 문구가 아니라 회사 내부 유동성 관리 기준이다. 상품 구매 화면에는 중도 해지를 의도적으로 강조하지 않으며, 중도 해지 조건은 Terms, Package Policy, FAQ에서 별도로 고지한다.

9. 매일 수익 분배 정책

패키지 수익은 매일 내부 Ledger로 분배한다. 이는 온체인 송금이 아니며, 유저별 Earnings Balance에 장부상 적립된다. 수익 분배 후 Withdrawal Balance가 업데이트되고, 그 잔액이 출금 요청 기준이 된다.

  1. 일일 패키지 수익 계산
  2. Earnings Balance 적립
  3. Withdrawal Balance 업데이트
  4. 출금 신청 마감 기준 적용
  5. 출금 주소 검사 및 배치 출금 대기열 반영

10. 출금 정책

출금 주소 제한 정책

LONGRISE는 중앙화 거래소처럼 매 출금마다 임의의 주소를 입력하는 구조를 사용하지 않는다. 유저는 사전에 등록된 출금 주소로만 출금할 수 있으며, 1단계부터 출금 주소는 메인 주소 1개와 서브 주소 1개로 제한한다. 이 구조는 잘못된 주소 입력, 피싱 주소 전송, 한국 거래소 직접 출금, 반복적인 블랙리스트 검사 부담을 줄이기 위한 정책이다.

항목 정책 운영 효과

변경 직후 출금 운영 정책에 따라 대기 시간 적용 가능 긴급 주소 변경 후 즉시 출금되는 위험을 낮춘다.
블랙리스트 검사 주소 등록/변경 승인 시 집중 검사 출금 요청마다 전체 검사를 반복하는 부담을 줄인다.

12. 내부 SEND 정책

SEND는 플랫폼 내부 유저 간 USDT 이전 기능이다. 이는 외부 지갑으로 나가는 온체인 출금이 아니며, 플랫폼 내부 Ledger에서 송신자의 Withdrawal Balance를 차감하고 수신자의 Deposit Balance 또는 Internal Received Balance로 증가시키는 장부 이전이다. SEND는 입금/출금과 함께 월렛의 핵심 자금 이동 기능으로 취급하되, 온체인 TxID가 생성되지 않는다는 점을 명확히 구분한다.

항목 정책 유저 화면 기준
전송 대상 플랫폼 내부 유저 수취 유저명 또는 플랫폼 고유번호로 확인
전송 자산 USDT Withdrawal Balance에서만 전송 가능
사용 불가 잔액 Bonus USDT, Package Value, CNYT, 검토 중 입금액 전송 가능 잔액에 포함하지 않음
수수료 1단계 무료 권장 내부 장부 이전이므로 네트워크 수수료 없음
취소 가능 여부 완료 후 취소 불가 전송 전 수취 유저와 금액 재확인 팝업 표시
히스토리 Transfer History에 기록 TxID 대신 내부 Ledger ID와 상세 로그 표시
  • SEND는 온체인 송금이 아니라 내부 Ledger 이전으로 처리한다.
  • 검토 중인 입금액, 고위험 자금, Bonus USDT, CNYT는 USDT SEND 재원으로 사용할 수 없다.
  • 송금 전 수취 유저명 또는 고유번호와 금액을 재확인하는 확인창을 표시한다.
  • 송금 성공, 잔액 부족, 송금 실패 결과를 팝업으로 명확히 표시한다.
  • 완료된 SEND는 취소할 수 없으며 내부 Ledger ID를 발급한다.
  • 히스토리에는 송신자, 수신자, 일시, 금액, 상태, 내부 로그 ID를 기록한다.

13. CNYT 보관 및 내부 P2P 정책

CNYT는 외부 지갑 출금을 지원하지 않는다. 유저가 보유한 CNYT는 플랫폼 내부 Ledger 잔액으로 표시하며, 유저 간 이전은 플랫폼 내부 P2P 게시판을 통한 장부상 이동으로만 처리한다.

항목 정책 개발 반영
CNYT 외부 출금 지원하지 않음 외부 지갑 주소 입력, 온체인 CNYT 출금 API, 출금 히스토리 UI를 제공하지 않는다.
CNYT 내부 P2P 게시판 체결 후 Ledger 이전 매도자, 매수자, 수량, 가격, 체결 상태, 로그 ID를 기록한다.
CNYT Central Wallet 회사 보유 중앙 지갑 존재 발행, 보유, 분배, 회수, 리워드 지급의 기준 지갑으로 관리한다.

14. 오염 자금 및 고위험 USDT 대응

  1. 고위험 입금의 자동 반영을 중단한다.
  2. 관련 유저의 출금과 SEND를 일시 제한한다.
  3. 해당 자금은 정상 자금과 혼합하지 않고 Quarantine Wallet 정책을 적용한다.
  4. 체인 분석 리포트와 내부 검토 기록을 생성한다.
  5. 필요 시 유저에게 추가 확인을 요청한다. 단, KYC 자료 수집을 전제로 하지 않는다.
  6. 동일 출금 주소, 다계정 패턴, 추천망, 내부전송 이력을 점검한다.
금지: 고위험 자금을 잘게 쪼개거나 여러 지갑으로 분산해 이동하는 방식은 사용하지 않는다. 이는 리스크 회피가 아니라 의심거래 패턴으로 해석될 수 있다.

16. 유저별 컨트랙트 지갑 검토

중앙화 수탁형 구조에서는 유저별 컨트랙트 지갑이 기본 요구사항이 아니다. EOA 또는 HD Wallet 파생 주소를 입금 식별용으로 사용하는 편이 비용과 운영 측면에서 적합하다. 컨트랙트 지갑은 배포 비용, 보안 감사, 체인별 구현 차이, 회수 비용이 발생하므로 특수 기능이 필요할 때만 별도로 검토한다.

컨트랙트 지갑 배포 비용 발생 기본 권장 아님
Account Abstraction 첫 사용 또는 배포 시 비용 발생 향후 특수 UX 필요 시 검토

18. 최종 결론

  • 플랫폼은 KYC 없는 Web3 수탁형 지갑 구조를 기본으로 한다.
  • 유저는 이메일과 플랫폼 고유번호로 구분하며 다계정 생성을 허용한다.
  • 1단계는 회원 100명 미만, 2단계는 100명 이상, 3단계는 1000명 이상으로 정의한다.
  • USDT 입출금은 TRC20으로 시작하고, 3단계 이후 테더 주요 상위 3개 체인으로 확장한다.
  • 집금 정책은 1단계부터 적용하며, 유저 입금 자금은 Stage-1 Collection Wallet로만 모으고 Payout Wallet 또는 CEX로 직접 이동하지 않는다.
  • Payout Reserve는 총 확정 패키지 구매금액의 35%를 기준으로 단순 관리하며, 매월 10일과 25일에 충전 상태를 점검한다.
  • Payout Reserve가 필요액의 90% 미만이면 주의 경보, 80% 미만이면 긴급 경보로 처리한다.
  • 한국 거래소와의 직접 입출금만 차단하고, 개인지갑을 경유한 거래는 차단하지 않는다.
  • 출금은 사전 등록된 메인 1개/서브 1개 주소로만 가능하며, 주소 변경은 OTP 인증과 관리자 승인을 거친다.
  • 유저의 주요 입금 수단은 Binance, Trust Wallet, imToken을 전제로 한다.
  • 매일 수익은 내부 Ledger로 분배하며, 출금은 UTC 09:00 기준 1일 1회 처리한다.
  • SEND는 플랫폼 내부 유저 간 USDT 장부 이전으로 처리하며, 온체인 TxID 없이 내부 Ledger ID를 발급한다.
  • 1단계 최소 출금액은 Flexible 상품 UX를 고려해 10 USDT로 설정한다.
  • 1단계 TRC20 출금 수수료는 1 USDT 고정으로 운영하고, 2단계부터 현실화를 검토하며, 3단계에서 Energy 임대 기반 최적화를 검토한다.
  • CNYT는 외부 지갑 출금을 지원하지 않고, 내부 P2P 게시판을 통한 Ledger 이동만 허용한다.
  • 오염 가능 자금은 정상 자금과 혼합하지 않고 Quarantine Wallet 정책으로 격리한다.
