모바일 뷰 개발 핸드오프 노트

이 문서는 정적 시안(standalone HTML)을 실제 플랫폼으로 옮길 때 필요한 아키텍처·기획 의도와, 시안에서 가짜로 처리된 부분 / 서버에서 내려와야 하는 데이터의 경계를 정리한 것입니다. 구현 코드가 아니라 의도와 데이터 계약 중심으로 봐 주세요.

Server 서버 API가 실제 값으로 내려줘야 함 (현재 하드코딩)
Mock 동작은 흉내만 냄 — 실제 처리/검증 엔드포인트 필요
Client 클라이언트 전용 (현 상태 유지 가능)
01

이게 무엇인가

하이파이 인터랙티브 시안. 실거래·실자금·백엔드 없음.

  • 모바일은 PC의 반응형이 아니라 별개 인터페이스다. 브레이크포인트를 넘어가면 PC를 좁힌 게 아니라 완전히 새로운 UI로 전환되는 설계. 하단 탭 네비 기반 모바일 앱 패턴 — PC의 사이드바/2단 그리드와 무관.
  • 소스 구조. LONGRISE Mobile.html + app/ (React, 화면별 파일 분리). 배포용 단일 파일 LONGRISE Mobile Standalone.html 은 이 소스를 컴파일·인라인한 산출물이라 직접 수정 대상 아님.
  • 상태/지속성. 앱 상태는 메모리(React state)만 사용. localStorage 는 디자인 검토용 Tweaks 값에만 쓰임 — 실제 세션/토큰 저장 아님.
02

구조 & 기획 의도

앱 셸 = 상단 헤더 + 하단 5탭 네비 + 풀스크린 오버레이. 화면 간 이동은 전부 탭/오버레이 전환이며 페이지 새로고침이 없다.

영역의도
EARN (홈)기본 진입 화면 = 대시보드. 총자산 · 보유 패키지 · AI 엔진(선물 캔들 차트 + 라이브 통계) · 라이브 체결 피드 · 7일 수익 · 공지.
PLANS투자 상품/패키지 카탈로그. 구매 진입.
NETWORK레퍼럴/팀 — 조직도, 추천 실적, 커미션, 랭크.
WALLET자금. 입금·출금·송금·스왑을 바텀시트 플로우로 처리.
ALL전체 메뉴 허브. 사이드바/드로어를 대체하는 핫링크 모음 — 모바일에선 드로어 대신 탭으로 둔다는 의도.

오버레이 계층

  • 로그인 시퀀스. 동의 게이트(매 로그인) → 중요 공지 팝업(설정 시) → 신규 유저용 Start Here 넛지. 신규/기존 유저 분기는 Tweaks에서 토글 가능.
  • Start Here = 앱 내부 온보딩 가이드. 외부 페이지가 아니라 앱 안 풀스크린 오버레이. 진입점 3곳(홈 상단 배너 · ALL 탭 · 신규 유저 팝업). Buy→Earn→Grow→Repeat 루프를 설명하고 각 CTA는 해당 탭/플로우로 직접 라우팅.
  • 하단 네비 스택 규칙. 네비는 Start Here·프로필 같은 풀스크린 오버레이 위에 떠서 항상 이동 가능. 단 바텀시트(입출금)·팝업·로그인 화면에서는 가려짐. (z-index: 네비 46 / 페이지 오버레이 45 / 시트 50 / 팝업 65 / 로그인 70)
  • Tweaks 패널. Client 디자인 검토용 토글(골드 강도, 모션, 라이브 피드, 유저 상태). 실제 제품엔 포함 안 함.

04

시안에서 가짜로 처리된 동작 Mock

UI 플로우는 완성돼 있으나 실제 검증/처리 없이 낙관적으로 성공 처리됨. 각 항목은 대응 엔드포인트와 상태 머신이 필요.

  • 동의 게이트. 매 로그인마다 리스크 고지 + 약관 개별 동의. 현재 client-only. → 동의 사실과 문서 버전을 서버에 기록해야 함.
  • 입금. 네트워크 선택(TRC-20/ERC-20) → 주소 발급 → "보냈음" → pending. 실제로는 유저·네트워크별 주소 발급 + 온체인 컨펌 감시(예: 12 confirmations) 후 크레딧.
  • 출금. 금액 → 목적지 → 2FA OTP(Google Authenticator) → 제출. 현재 6자리면 무조건 통과. 실제: OTP 검증, 1.5% 수수료, 잔액 검증, 일괄 정산(00:00–02:00 UTC 배치), 출금 PIN.
  • 송금(내부 이체). 즉시 정산 가정. 수취인 검증(주소/유저ID)·한도·중복 방지 필요.
  • 스왑. earned USDT → CNYT, 고정 환율 7.08 하드코딩. 실제 호가/슬리피지/체결 환율 필요.
  • 패키지 구매. PLANS의 구매 진입은 UI만. 잔액 차감·계약 생성·락업·일ROI 적립 로직 필요.
  • 알림·지원·문서·설정·로그아웃. 현재 토스트로 "preview only" 처리. 각각 실제 기능/화면 연결 필요.
05

AI 엔진 차트 & 라이브 피드 Mock

EARN 화면의 핵심 비주얼. 현재 전부 클라이언트가 난수로 생성하는 연출이다.

선물 캔들 차트
캔버스 엔진(LRChart)이 캔들·EMA·AI 스캔 빔·매수/매도 시그널을 자체 생성. → 실제 가격 캔들 스트림(웹소켓)과 엔진 시그널로 교체. 차트는 "엔진이 일하는 중" 연출이 기획 의도.
라이브 체결 피드
genTrade() 가 랜덤 체결을 3초마다 생성. → 실제 엔진 체결 이벤트 스트림으로 교체.
엔진 통계
승률·일ROI·시그널/초·지연. 차트 콜백으로 시그널/지연만 흔들어줌. → 실측 메트릭.
모션 제어
애니메이션은 prefers-reduced-motion 과 인앱 "Live feed" 토글을 따름. 정지 시 마지막 프레임 표시.
06

비주얼 시스템

  • LRHP 디자인 시스템. 다크 + 골드. 모든 색/타입/스페이싱은 CSS 토큰(var(--*)). 폰트는 디스플레이 세리프 / 본문 / 모노 3종.
  • 레이아웃. 폰 폭 컬럼(최대 430px) 고정 높이 셸 + 내부 스크롤. 하단 네비 바닥 고정. 넓은 화면에서도 폰 컬럼 유지(데스크탑 확장 안 함).
  • 색 의미. 골드=강조/브랜드, 그린=유입/수익, 레드=유출/손실. 데이터 색상은 이 규칙을 따름.
07

알려진 시안 한계 / 주의

용어는 임시 라벨이다. 탭/화면 명칭(Plans·Network·Earn 등)은 확정 전 임시값 — 추후 일괄 통일 예정. 매핑은 Glossary.html 참조.

  • 모든 숫자·날짜·주소는 데모 값. 통화/소수 자릿수·타임존(UTC 기준 정산) 등 표기 규칙은 서버 응답에 맞춰 확정.
  • 인증·세션·권한 없음. 실제 로그인/토큰/리프레시 흐름은 미구현.
  • CNYT·ROI·랭크·커미션 등 비즈니스 로직은 시안 수치가 아니라 확정 정책 기준으로 구현.
  • i18n 미적용(현재 영문 카피). 다국어 시 레이아웃 여백 재검토 필요.
