Developer Handoff

LONGRISE Wallet / Withdrawal / SEND 개발 지시서

이 문서는 개발자가 서버와 프론트 기능을 연결할 때 필요한 구현 기준이다. UI/UX 화면 재기획은 기획자 업무이며, 개발자는 확정된 화면에 아래 정책과 상태값, API, 관리자 기능을 연결한다.

핵심 결론: 유저 화면은 출금 주소 관리와 출금 정책 고지가 추가 재기획 대상이다. SEND와 CNYT는 기존 기능을 유지하되 확인/취소불가 고지만 보완한다. 입금/집금 관리와 Payout Reserve는 관리자툴에 구현한다.

1. 업무 분리

구분담당해야 할 일
유저 UI/UX 재기획기획자출금 주소 등록/변경 화면, 출금 정책 고지, SEND 최종 확인창, CNYT 내부 이동 화면, Terms 입출금 섹션을 설계한다.
서버/프론트 연동개발자확정된 UI에 API, DB 상태값, Ledger, OTP, 관리자 승인, 배치 출금, 히스토리 표시를 연결한다.
관리자툴개발자입금/집금 상태, 출금 주소 승인, 출금 배치, Payout Reserve 상태와 경보를 구현한다.
내부 개발 단계개발/운영1단계 100명 미만, 2단계 100명 이상, 3단계 1000명 이상 기준은 유저에게 노출하지 않고 개발 우선순위 기준으로만 사용한다.

Payout Reserve총 확정 패키지 구매금액의 35%를 기준으로 필요 Reserve를 계산한다. 매월 10일/25일 점검한다.관리자툴
Reserve 경보필요액 90% 미만은 WARNING, 80% 미만은 CRITICAL로 표시한다.관리자툴

5. 내부 개발 단계

아래 단계는 개발자 작업 지시와 운영 확장 기준이다. 유저 화면에는 표시하지 않는다.

단계기준개발 범위
1단계회원 100명 미만TRC20 USDT, 19 컨펌, Ledger, SEND, 주소 승인, UTC 09:00 배치, Stage-1 Collection, 관리자 수동 확인.
2단계회원 100명 이상Buffer/Vault/Payout 역할 분리, 한국 거래소 직접 입출금 자동 차단, Basic On-chain Risk Screening, 수수료 현실화 검토.
3단계회원 1000명 이상Energy 임대 연동, 지갑 유동성 알림, 고액 출금 승인 룰 고도화.
3단계 이후안정 운영 후TRC20 외 테더 사용량 상위 3개 체인 순차 지원.

6. Ledger 잔액 타입

잔액은 하나의 숫자로 저장하지 않는다. 자금 성격별 원장 항목을 분리하고 화면 잔액은 계산값으로 표시한다.

balance_type의미출금SEND
deposit_principal상품 구매 전 유저 입금 원금가능가능
purchase_remainder상품 구매 후 남은 잔금가능가능
earning_usdt상품 구매에 따른 월/일 배당 수익가능가능
bonus_usdt기프트 카드식 보너스 USDT불가불가
package_value상품에 묶여 있는 구매 금액불가불가
pending_withdrawal출금 신청 후 대기 중인 금액불가불가
locked_review검토/제한 중인 금액불가불가
available_cnyt내부 P2P 가능한 CNYT외부 출금 불가USDT SEND 불가
staked_cnyt잠금 상태 CNYT외부 출금 불가USDT SEND 불가

9. API 구현 메모

API역할필수 검증
GET /api/wallet/deposit-address유저별 TRC20 입금 주소 반환.유저 상태, 체인, 주소 발급 여부.
