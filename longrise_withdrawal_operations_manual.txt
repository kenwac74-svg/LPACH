LONGRISE 입출금 및 운영 통제 실무 매뉴얼 (Daily Action Guide)

목적: v2.0 정책에 의거하여 개발팀, 운영/CS팀, 최고 재무 관리자(Admin)가 매일 수행해야 할 입출금 처리 및 시스템 통제 업무를 시간순 및 상황별로 명확히 규정한다.

1. 개발자 (Backend/Infra Engineer) Daily Guide

상시 모니터링 (Automated & Real-time)

입금 감지 데몬(Daemon) 상태 확인

TRON(TRC-20) / BSC(BEP-20) 노드와의 연결 상태 및 블록 동기화 딜레이 확인.

데몬 장애 발생 시 즉각 재시작 및 누락된 블록 구간 수동 재스캔 (Rescan).

API 및 데이터베이스 Health Check

출금 대기열(Queue) DB 데드락(Deadlock) 여부 모니터링.

REJECTED 또는 FAILED 상태의 출금 건에 대한 롤백(Rollback) 스크립트 정상 작동 여부 1일 1회 검증.

이슈 발생 시 Action Plan

이중 지불(Double-Spend) 의심 로그 발생 시:

즉시 슬랙(Slack) '긴급-인프라' 채널에 보고 (To: 시스템관리자, 운영팀).

출금 Queue 처리 스크립트(Batch) 임시 중단 (Kill Process).

DB 트랜잭션 로그 분석 후 원인 파악 및 수동 보정.

유저 입금 누락 (Slippage 발생) 시:

운영팀에서 인입된 TxID 온체인 데이터 수동 교차 검증.

스크립트 오류로 인한 누락 시, DB에 인게임 잔액(USDT) 수동 크레딧 처리.

2. 운영/CS 담당자 (Operations & CS) Daily Guide

Daily Routine (2회/일: 오전 10시, 오후 4시)

[1단계: 출금 대기열 1차 심사 (Screening)]

어드민 페이지 접속 -> 출금 관리 -> PENDING (대기) 리스트 확인.

어뷰징 필터링:

동일 IP / MAC Address에서 다수 지갑 출금 요청 시 상태를 REJECTED로 변경 후 '다계정 의심' 메모 작성. 계정 상태 Suspended 전환.

24시간 내 비정상적 고액 배당 발생 계정은 상태를 PROCESSING (처리 중)으로 변경 후 개발팀에 데이터 검증 요청.

정상 건 분류: 어뷰징 혐의가 없는 건들을 선택하여 상태를 PROCESSING으로 일괄 변경.

[2단계: 출금 리스트 추출]

PROCESSING 상태의 출금 리스트를 엑셀(CSV) 파일로 다운로드.

최고 재무 관리자(Admin)에게 해당 파일 송부 및 최종 승인 요청.

이슈 발생 시 Action Plan (CS 대응)

유저: "입금했는데 패키지 구매가 안 됩니다."

대응: "고객님, 입금액이 패키지 금액보다 부족하여(수수료 차감 등) 인게임 잔액으로만 적립되었습니다. 부족분을 추가 입금해 주시기 바랍니다."

유저: "한국 거래소(업비트 등)로 출금하고 싶습니다."

대응: "본 플랫폼은 트래블룰을 준수하여 한국 거래소로의 직접 출금을 금지합니다. 바이낸스 등 해외 거래소 또는 개인 지갑 주소를 등록해 주십시오."

유저: "지갑 주소를 변경해 주세요."

대응: 신분증(KYC) 사진과 이전 지갑의 소유권을 증명할 수 있는 화면 캡처 요구. 증빙 완료 후 '운영 매니저'에게 주소 변경 승인 상신.

3. 최고 재무 관리자 (System Admin / CFO) Daily Guide

Daily Routine (2회/일: 오전 11시, 오후 5시)

[1단계: 핫월렛(무균실) 잔액 점검]

출금 전용 핫월렛(Withdrawal Wallet)의 USDT 잔액 확인.

가스비 지불을 위한 TRX 및 BNB 잔액 확인. 부족 시 법인 클린 자금 지갑에서 수동 충전(Funding).

[2단계: 최종 승인 및 송금 집행 (Batch Execution)]

운영팀에서 전달받은 PROCESSING 상태의 엑셀(CSV) 리스트 수령 및 검토.

이상 없음 확인 후, 보안 환경(클린 PC)에서 송금 스크립트 실행 또는 어드민 페이지 '일괄 전송(Batch Send)' 버튼 클릭.

보안 단계: 출금 승인 시 반드시 등록된 Google OTP (2FA) 인증 코드 입력.

송금 완료 후, 해당 건들의 상태를 APPROVED -> 온체인 확인 후 COMPLETED로 최종 변경 확인.

이슈 발생 시 Action Plan

운영팀의 주소 변경 요청 인입 시:

증빙 서류 검토 후, 타당하다고 판단될 경우에만 어드민 권한으로 DB 지갑 주소 강제 업데이트 (OTP 인증 필수).

핫월렛 해킹 의심 징후 (비정상 트랜잭션) 포착 시:

즉시 핫월렛 내 남은 자금을 전액 오프라인 콜드월렛(Cold Wallet)으로 대피(Sweeping).

개발팀에 통보하여 프론트엔드/백엔드 출금 기능 전면 차단 (Maintenance Mode 전환).

사태 파악 후 사내 공지 및 후속 조치 지시.

전체 시스템 흐름도 (Workflow Summary)

유저 출금 신청 -> DB 상태: PENDING -> 운영팀 1차 심사 -> 정상 건 PROCESSING -> 최고 관리자 최종 승인 -> APPROVED -> 온체인 송금 스크립트 실행 -> 성공 시 COMPLETED.

어뷰징/한국거래소 출금은 REJECTED 및 DB 자동 롤백 처리.

가스비 부족/네트워크 오류는 FAILED 및 DB 자동 롤백 처리.
